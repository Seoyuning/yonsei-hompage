### 3.4 충실도 만점용 추가 깊이 요소 (이 학부 특화)
1. **교수×연구실×교과목×뉴스 4-way 연결**: 동일 태그/PI키로 상호 링크(현 사이트는 단절). 한 교수 페이지에서 그의 랩·담당과목·최근공지 자동 노출.
2. **연혁 인터랙티브 타임라인**: PART1.2 13개 마일스톤을 연도 스크롤 컴포넌트로(1958→2020). 50주년·BK21 4단계 강조.
3. **사이트 검색(현재 전무)**: 위 JSON들을 단일 인덱스로 묶어 교수명/랩/과목/공지 통합검색 — 사용성 30점에 직접 기여.
4. **공지 5종 분류 유지**(학부/대학원/외부/장학/뉴스)하되 태그 필터 추가 — 현 IA의 정보밀도 과다 문제를 필터로 해소.

## 3) 기계공학과 특화 시그니처 요소 (3D·인터랙티브·데이터시각화) — 3 사례

대회 차별성(창의성 10)과 'ME다움'을 동시에 잡는 ME 전용 요소. **에셋은 자작 또는 CC 라이선스+출처표기 필수**(§5 유의사항).

1. **인터랙티브 3D 부품 뷰어 (Exploded View)** — MIT의 "Building Hardcore Machines" 영상 정체성을 **영상에서 조작 가능한 3D로 업그레이드**. 엔진/터빈/로봇 관절을 드래그·스크롤로 분해·회전. 기술: **`<model-viewer>`(GLB) 또는 Three.js**, `prefers-reduced-motion` 대체 정지컷. 에셋: 자작 간단 CAD를 GLB로 내보내기(타기관 모델 무단 금지). 적용: 연구임팩트 히어로 또는 '연구실 들여다보기' 1개 랩 데모.
2. **연구 분야 인터랙티브 네트워크 맵** — KAIST 4타일/`ME+AX·반도체·BATTERY` + Berkeley "Faculty by Research Area"를 **force-directed 그래프**로: `연구분야 — 교수 — 연구실`을 노드로 연결, 노드 클릭 시 §2-⑥ 모아보기로 라우팅. 기술: **D3/force-graph(정적 JSON 데이터 구동)**. 이것이 데이터시각화 시그니처이자 정보구조 점수의 핵심.
3. **데이터 'By the Numbers' + 성과 미니차트** — GT 통계밴드를 한 단계 올려 **연도별 논문·연구과제비·동문 진로분포**를 소형 인터랙티브 차트(막대/도넛)로. 기술: 경량 SVG 차트(자작) — 무거운 라이브러리 회피로 성능 유지. **모든 수치는 실데이터만**(없으면 차트 미게시).

(보조) 로보틱스/유체 시뮬 **영상 루프 히어로**(MIT 패턴)는 3D 에셋 준비가 늦어질 경우의 폴백.

- **별도 /en 사이트의 방치·불일치** — 영문이 본문과 따로 놀고 오래 미갱신(현행 /me_en 별도운영).
- **모든 콘텐츠를 '게시판(BBS)'로** 사고 — 태깅·스토리텔링·관계연결 부재.
- **핵심 정보를 PDF/HWP 첨부에 은닉**(서식·공지) — 본문에 없어 검색·접근성·모바일 모두 실패.
- **테이블 기반 고정폭 레이아웃 + 정보밀도 과다 + 여백 부재**(현행 진단과 일치) — 2010년대 초반 인상.
- **히어로 부재·약한 브랜딩** — 첫 화면이 학과 정체성을 못 전달.
- **형식만의 접근성**(skip-link는 있으나 색대비·포커스·alt 미흡), **인증마크/품질 시그널 없음**.
- **자동재생 팝업·공지 레이어**, 구형 보안프로그램/ActiveX 잔재.
- **유령 게시판**(세미나·영문·자료실의 최신글이 수년 전) — 운영 안 됨을 자백.
- **시스템 폰트 의존·타이포 위계 약함**(현행 진단과 일치).

각 항목이 '지는' 이유: 위 다수는 UX 30·기술 30·정보구조 20에 **직접 감점**이며, 무엇보다 **교수진이 "이건 우리가 못 굴린다/구식이다"**라고 판단하면 채택 프레임에서 탈락.

## 5) '교수진이 신뢰할 기관급 완성도' 디테일 체크리스트

채택 결정권자(교수진)가 **"인수해서 실제로 운영 가능"**이라 믿게 만드는 항목. 굵게 = 이 대회 결정타.

**A. 운영·유지보수(요건 명시 + B2B 채택의 핵심)**
- [ ] **비개발자(조교·행정)가 공지·교수·연구실을 수정 가능한 구조** — Markdown/경량 CMS(Decap/Sveltia) 또는 Google Sheet→빌드. *수정·유지관리 용이성은 기술요건에 명시됨.*
- [ ] 교수/연구실/공지 = **단일 데이터 소스(JSON/CMS)에서 자동 생성** — 손수 HTML 페이지 금지(확장·정확성).
- [ ] **운영 가이드 문서**(공지 올리는 법·교수 추가법·배포법) + README → "인수 후 굴릴 수 있다"는 증거.

**B. 정보 정확성·거버넌스(★사실 날조 금지)**
- [ ] 모든 사실(교수 실명·직함·연락처·수치)에 **출처 URL·최종확인일** 메모. **출시 전 placeholder 0건.**
- [ ] **수집 체크리스트(정확 URL 적시)**: 교수진 `me/faculty/professor_list.do` · 연구실 `me/research/lab2.do` + `me/graduate/labs.do` · 영문 `me_en/index.do` · 열공학센터 `mes.yonsei.ac.kr` · 연락처 학부 02-2123-4426 / 대학원 02-2123-2810 / 03722 서울 서대문구 연세로 50.
- [ ] By-the-Numbers 수치(교수·연구실·재학생·동문 N)는 **학부 사무실/대학알리미 확인 후** 게시 — 미확인 시 미게시(검증필요).

**C. 웹표준·접근성(KWCAG/WCAG)**

- [ ] 시맨틱 HTML, 페이지당 단일 H1, **JSON-LD**(Organization·Person(교수)·BreadcrumbList), OG/메타, `sitemap.xml`/`robots.txt`, HTML 검증 통과.

**D. 성능·반응형**
- [ ] Lighthouse **95+** / LCP <2.5s / CLS <0.1. 이미지 **AVIF·WebP + lazy**, **한글 폰트 subset**, **Pretendard self-host**(라이선스 적합).
- [ ] 360·768·1280 실측, **가로 스크롤 0**, 터치타깃 ≥44px.

**E. 브랜딩·법적(유의사항 직결)**

## 2) 루브릭에 없지만 '채택 결정'을 좌우하는 숨은 기준 Top 7 (채택결정력 순)

1. **운영 이양 가능성 — "졸업하면 사이트도 죽는가?" (숨은 1순위)**
   교수의 진짜 공포. 학생이 떠난 뒤 교직원/학교 정보화팀/외주가 굴릴 수 있어야 한다. → **관리자 UI(또는 Markdown/시트 기반 콘텐츠) + 운영 매뉴얼 + 인수 패키지**로 정면 격파. 이게 없으면 아무리 예뻐도 "재밌었지만 채택은 못 해"가 된다.

2. **콘텐츠 정확성 — 교수 본인 데이터**
   이름 오타·직함 오류·엉뚱한 연구분야는 **감점이 아니라 모욕**이다. 반대로 전원 정확하면 "성실+우리 학부를 존중한다"는 신뢰가 사이트 전체로 번진다. 교수는 **자기 페이지를 가장 먼저** 본다.

3. **기관 품위 — '연세 공대급' 무게감**
   스타트업 랜딩페이지(네온 그라데이션·과한 모션)는 부적합. **톱3 대학 대표 공대다운 절제된 격**이 필요. 화려함이 아니라 '품위 있는 현대성'이 만점 정서.

4. **리스크 제로 — 망신·법적 노출 없음**
   교수는 극도로 손실회피적. **저작권·상용폰트·타기관 로고·교수 사진 무단사용·개인정보(이메일·휴대폰 노출)·보안 구멍** 단 하나만 보여도 우수작이 침몰. 유의사항에 명시된 항목이라 **결격 트리거**.

5. **마이그레이션 현실성 — 학교 인프라가 받을 수 있나**
   현행은 JSP/.do CMS + 정보화팀/외주 체계. "이 스택을 학교가 인수 가능한가"가 숨은 통과 조건. **정적 export 가능 / 표준 스택 / 데이터 이관 경로**를 제시하면 "도입 현실성 있다"로 가산.

6. **웹접근성 = 공공기관급 법적·민원 리스크 회피**
   대학 사이트는 **장애인차별금지법·웹접근성** 대상. 단순 가점이 아니라 "안 하면 나중에 민원·인증 문제". 아는 교수는 이걸 무겁게 본다 → **대비 AA·alt·키보드 내비·skip-link**로 "운영 리스크까지 챙겼다" 신호.

7. **교수 셀프편집·셀프점검 경험**
   교수가 **직접 만져보는 순간**(자기 이름 검색→정확한 페이지, 또는 공지 1건 올려보기)이 신뢰의 분기점. 교수진 섹션과 관리자 데모를 **가장 정확하고 가장 셀프서비스 가능**하게 만들면 사이트 전체 평가가 올라간다.

## 3) 학생팀이 점수를 잃는 실패모드 10 + 회피책

1. **가짜·빈 콘텐츠(‘준비중’·lorem·더미 교수)** — 최대 살인마. 교수가 클릭해 빈 페이지를 본다. → **100% 실데이터로 채우고**, 실데이터 못 채울 섹션은 **가짜로 넣지 말고 빼라**.
2. **모바일 깨짐** — 심사장에서 **본인 폰으로 연다**. 표 오버플로·작은 탭타깃·잘린 히어로. → 모바일 퍼스트, 360px 실기기 테스트를 데모 전 필수.
3. **교수 데이터 오류(이름·직함·연구분야·사진)** — 정서적 치명상. → 전 항목 소스 대조 검수, **정교수/부교수/조교수/특임 직함 정확히**, 가능하면 교수 1인에게 사전 검수.
4. **접근성 무시(alt·대비·키보드)** — 공공 사이트 법적 노출. → 대비 AA, ARIA, 키보드 내비, skip-link, a11y 점수 제시.
5. **과한 효과·모션 슬롭(불필요 패럴랙스·자동재생·요란한 그라데)** — '학생 포폴'로 읽혀 심미(부적합)+성능 동시 하락. → 목적 있는 절제된 모션, `prefers-reduced-motion` 존중.
6. **성능 저하(거대 이미지·무거운 JS)** — 느린 데모 = 무능의 가시화. → 이미지 최적화(WebP/AVIF·`next/image`), 정적 생성, lazy-load, **Lighthouse 90+**.
7. **유지보수 불가(하드코딩·이양계획 없음)** — 교수 숨은 1순위 공포 직격. → 콘텐츠를 CMS/DB/Markdown으로 분리, **관리자 데모 + 인수인계 문서**.
8. **발표 부실 / "이거 진짜 너희가?"** — 슬라이드 읽기, 기술 Q&A 막힘, AI 과의존 의심. → 라이브 데모 리허설, 아키텍처 본인 설명, **GitHub 커밋 히스토리로 저작 입증**.
9. **저작권·브랜드 위반(무단 폰트·타교 템플릿·연세 로고 오용·교수 사진 무단·연락처 노출)** — 명시된 결격 사유. → **Pretendard 등 무료상용 폰트**, 라이선스/자작 에셋, **연세 BI 가이드 준수 색·엠블럼**, 모든 출처 명시, 개인정보 마스킹.
10. **현행 사이트·기관 맥락 무시(그냥 멋진 남의 사이트)** — ME의 실제 IA·한/영·입시·취업 니즈를 무시한 제네릭 템플릿. → **현행 6-메뉴 전부 신 IA로 매핑**, 한/영 통합, 현행 페인(모바일·검색·디자인) 명시 해결, **Before/After** 제시.

## 2) '경쟁작 평균 수준' — 여기를 넘어야 입상, 더 넘어야 1등

경쟁작 전부가 **빈 껍데기**다. 우리는 진짜 학부를 통째로 채운다.

- **압도 장치 = 관계 그래프:** 교수↔연구실↔교과목↔연구분야를 **연결**(교수 클릭→그의 랩→담당 과목→인접 분야). 경쟁작은 평면 가짜 카드, 우리는 **항해 가능한 학부 지식그래프**.
- **증거 노출:** 단일 `data/` 진실원천(YAML/Supabase) + "마지막 갱신일" + 홈에 깊이의 증거를 카운트로: **"교수 OO명 · 연구실 OO개 · 교과목 OOO과목"**(정확 수치는 Day-1 스크랩으로 확정, 추정치 금지).
- **왜 해자인가:** 3.5주 안에 AI·템플릿이 **단축 못 하는 유일한 것**. 지금 시작 안 하면 못 따라옴.

### 축 2 — WCAG 2.2 / KWCAG 2.2 AA+ 접근성·웹표준 (기관급 컴플라이언스)
공공 대학 사이트는 **장애인차별금지법·웹접근성 의무** 대상. 학생 경쟁자는 아무도 진지하게 안 한다.
- **구현:** 시맨틱 HTML, 완전 키보드 내비, 가시적 포커스링, skip-link, 적절한 ARIA, prefers-reduced-motion, **검증된 AA+ 대비**, 제대로 된 heading 순서, 모든 교수 사진 alt, 폼 라벨. 글자크기·고대비 토글.
- **압도 장치 = 증명:** 발표자료에 **axe-core / Lighthouse 접근성 100 리포트** 첨부 + **"KWCAG 2.2 준수, 웹접근성 품질인증(WA 마크) 획득 가능 수준"** 명시 → 기관의 언어로 말하기.
- **프레임 전환:** 지루한 기능·콘텐츠 점수를 **컴플라이언스 논거**로 바꿈 → "타 작품 채택 시 학부는 *비준수*, 우리 건 *준수 완료*."

### 축 3 — 교수 셀프편집 CMS / 콘텐츠옵스 (도입의 결정타)
기술요건에 **"콘텐츠 수정·유지관리 용이성"** 이 명시. 교수진의 **말 안 한 1순위 공포: "학생 졸업하면 누가 고치나? 난 코드 못 만져."** 이걸 푼다.
- **구현:** Git 기반 헤드리스 CMS(무료·핸즈오프) — **Decap(구 Netlify CMS) / Sveltia / Keystatic / TinaCMS**. `/admin` WYSIWYG에서 **비개발자 조교·교수가 코드 안 만지고** 공지 작성·교수 추가 → Git 커밋 → 자동 재배포. (대안: 행정팀에 친숙한 Google Sheet/Notion-as-CMS.)
- **압도 장치 = 무대 위 라이브:** *"교수님 성함 주시면 지금 공지 하나 올리겠습니다"* → `/admin` 로그인 → 공지 입력 → ~30초 뒤 사이트에 반영. **이 한 장면이 좌중을 가져간다.**
- **산출물 차별:** **1쪽 '운영 인수인계 매뉴얼'**(편집권한 분리: 행정팀=공지 / 교수=본인 랩)을 디자인 산출물로 제출. **운영 문서를 내는 팀은 없다.**
- **의미:** "학생 프로젝트"→"도입 가능한 시스템"으로 건너가는 다리.

### 축 4 — 기계공학 정체성 시그니처 (템플릿이 못 흉내내는 것)
템플릿·v0는 *제네릭 대학/SaaS* 미감만 뽑는다. **"이것은 연세대 *기계*공학이다"** 를 표현하는 건 우리뿐 → 디자인 30 + 창의성 10을 가져옴.
- **시각 언어(절제된 엔지니어링 신뢰감):** 도면/블루프린트 모티프, 치수선(dimension line), 은은한 CAD 그리드 배경, 메커니즘 라인아트. 히어로엔 **경량 인터랙티브 1점**(기어트레인·4절 링크·터빈·응력장) — pure-CSS 또는 <50KB Three.js, **prefers-reduced-motion 존중**, 김삐는 금지.
- **분야 아이콘 = 실제 ME 기둥:** 열·유체 / 고체·설계 / 동역학·제어 / 생산·로봇·메카트로닉스 / 에너지·환경. 연세블루 + 엔지니어링 액센트(모눈 시안, 절제된 세이프티 오렌지). 타이포 = 클린 그로테스크 + 수치/스펙용 모노스페이스.
- **압도의 핵심 = 규율:** "포트폴리오"가 아니라 **"기관"** 으로 보일 것. **AI 슬롭 시그널 제거**(보라 그라디언트·글래스모피즘·이모지 불릿·전부 가운데정렬 금지). 이 *절제*가 그라디언트-blob React 군중 대비 차별점 그 자체.

### 축 5 — 한·영 동등 i18n + 성능 Lighthouse 100 (조용한 수월성)
영문 = **가점 명시**. 현 사이트는 `/me_en` 별도 운영(유지보수 악몽). 진짜 ME 학부엔 유학생·외국인 교원·리크루팅용 영어가 필수. 경쟁작은 영어를 빼거나 **구글번역 위젯**으로 때운다.
- **구현(구조적 i18n, 위젯 아님):** 단일 콘텐츠 모델·2로케일(**next-intl / Astro i18n / Paraglide**), 정확한 hreflang, `/ko`·`/en` 라우팅, **교수·연구실까지 전부 이중언어**(영문명은 `me_en`에서 수확), 토글이 현재 페이지를 유지.
- **성능 번들링:** static-first(**Astro 또는 Next SSG/ISR**), **모바일 포함 Perf/A11y/BestPractices/SEO 4×100 근접**, LCP <1s, 이미지 최적화(AVIF/WebP·교수 사진 사이즈드), prefetch.
- **압도 장치:** 발표자료에 **모바일 Lighthouse 4×100 스크린샷**. 시연 중 교수가 *자기 폰으로* 30초 안에 검증 가능한 지표에서 템플릿 군중을 압도. 속도+이중언어 = "운영적으로 진지하다"는 신호.

## 4) '1등과 2등을 가르는 단 하나의 결정적 차별점' — 가설 3개 + 채택 근거

### 가설 A — "월요일에 바꿔도 되겠다" 채택가능성(Adoptability)
> **1등 = 교수진이 *감상*이 아니라 *도입·운영*할 수 있다고 믿게 만든 유일한 팀.**
- **결정 레버:** 라이브 셀프편집 CMS(축3) + 실데이터 완전성(축1) + 인수인계 매뉴얼 → **도입 반대사유를 전부 제거**(누가 고치나? 데이터 진짜인가? 컴플라이언스 되나? 행정팀이 쓰나?).
- **근거:** 상품 자체가 *채택*("공식 홈페이지 기반으로 발전")이다. 심사위원은 예술비평가가 아니라 **운영자**. 대회를 디자인쇼→조달결정으로 재프레임하면, 그 결정에서 이길 자격은 우리뿐.

### 가설 B — "교수가 자기 자신을 검색했을 때"의 실데이터 충격(Data-truth)
> **결정적 순간 = 심사위원 교수가 *자기 페이지·자기 랩·자기 과목*을 찾았을 때, 완전·정확하고 관계그래프로 연결돼 있는 것.**
- **결정 레버:** "이 팀은 *우리에 대해* 진짜로 일을 했다"는 체감(visceral) — 어떤 애니메이션도 못 이김. 2등은 아름다운 빈 껍데기, 1등은 완전 채워진 실제 학부.
- **근거:** (1) 3.5주 안에 AI/템플릿이 못 베끼는 유일 항목, (2) 콘텐츠충실도+정보구조를 직접 증명, (3) **각 심사위원의 개인적 투자**를 유발(내 페이지가 멋짐 → 내 표).

### 가설 C — '하자 없음'의 기관 신뢰(Zero-defect institutional trust)
> **1등 = 기관이 거부할 *레드플래그가 0개*인 팀** — KWCAG/WCAG AA+ 통과, 모바일 Lighthouse 95~100, 한글 줄바꿈 무파손 반응형, 유효 HTML, 라이선스 문서화, 진짜 i18n.
- **결정 레버:** 자기 이름을 걸 사이트를 고르는 교수 위원회는 **손실회피적**이다 → 가시적 결함이 있는 작품을 *먼저 탈락*시키고, **살아남은 것 중 가장 완전한 것**을 택함. "깨끗한 품질·컴플라이언스 시트"를 가진 유일 제출물이 될 것.
- **근거:** 위원회 의사결정에서 **위험제거가 천재성을 이긴다**. "우리를 망신시키지 않을 / 접근성으로 소송당하지 않을" 방어 가능한 안전선택이 기관 구매에서 승리.

**전략적 베팅(셋의 결합):** **B를 감정적 후크**(노력·진실의 증명) → **A로 이성적 클로징**(도입가능성) → **C는 반드시 통과해야 할 탈락-스크린**. 즉 *느끼게(B) → 믿게(A) → 떨어뜨릴 구실 안 주기(C)*. 디자인 화려함(축4)은 **입장권**이지 결승점이 아니다 — 결승점은 **"실제로 운영 가능한 진짜 우리 학부 사이트"**.
